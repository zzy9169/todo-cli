# 待办清单（项目 01）

一个命令行的待办管理工具。任务存在本地 `user_info.json`，不联网、不需要数据库。

## 怎么跑

需要 Python 3.8 以上。

```bash
python 创建json.py
```

## 功能

| 输入 | 作用 |
|---|---|
| 1 | 新增一条待办（id 自动分配） |
| 2 | 查看全部待办 |
| 3 | 把指定 id 标记为已完成 |
| 4 | 结束程序 |

## 结构

```text
项目1/
├── 创建json.py      # 菜单、输入输出（界面层）
├── store.py         # load / save / find（数据层）
└── user_info.json   # 数据文件，程序自动创建
```

## 数据结构

```json
[
  {
    "id": 1,
    "content": "数学",
    "deadline": "2026-10-21",
    "status": "done",
    "create_time": "2026-10-21"
  }
]
```

`status` 只有 `todo` / `done` 两个值；日期用 ISO 格式（`YYYY-MM-DD`），这样按字符串排序就等于按时间排序。

## 我学到了什么

1. **界面层和数据层要分开。** 一部分负责读键盘指令，另一部分只负责读写数据（`load` / `save` / `find`），而不是一个主程序从头写到尾。拆完之后加功能不用改数据层。

2. **`load()` 每次返回的都是一份新副本，不是同一个列表。** 内存里存着启动时读到的那份，它不会跟着磁盘更新——之后再写回，就会用旧数据把新数据盖掉。所以每次操作都要现 `load()`。

3. **文件被改坏时，不能只是返回空列表。** 那样下一次保存会把坏文件整个覆盖，原数据就没了。现在的做法是先备份成 `user_info.json.bak`，再返回 `[]`。

4. **id 不能存成全局变量。** 启动时算一次的快照，删一条任务之后就不准了。改成每次新增时 `max(id) + 1` 现算。

## 已知限制

- `user_info.json` 损坏时会自动备份成 `user_info.json.bak`，然后重置为空清单，需要手工从 `.bak` 恢复
- 还没有删除、排序、按状态筛选
- 数据是全量读写：任务条数上万以后，每次操作都会变慢，那时候该换 SQLite
